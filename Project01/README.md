# Project01 - 움직이는 공을 손가락 총으로 맞추는 게임

`02_Computer-Vision.ipynb` - Section Project

초록색 공을 표적으로 검출하고 Kalman Filter로 추적하면서, 손가락 총 모양으로 조준해 **공이 이동할 위치를 미리 맞히는** 사격 시스템입니다. 검지로 조준하고 엄지를 접으면 발사되며, 탄이 날아가는 동안 공도 움직이기 때문에 현재 위치가 아니라 예측 위치를 겨눠야 명중합니다.

### 화면 표시
| 표시 | 의미 |
|---|---|
| 파란 원 | 이번 프레임에 실제로 검출한 공 위치 (측정값) |

## 3. 동작 과정

한 프레임마다 아래 순서로 처리합니다.

1. **이미지 조정**: 가로 960으로 축소(처리 속도), 좌우 반전(거울 모드)
2. **공 검출**: GaussianBlur → BGR→LAB → L 채널 CLAHE → `inRange` 마스크 → Opening 2회 → Closing 3회 → 가장 큰 contour 선택 → 외접원 반지름, 무게중심
3. **공 추적**: 보이면 Kalman `predict()` + `correct()`, 가려지면 `predict()`만 수행, 30프레임 이상 안 보이면 추적 종료
4. **손 인식**: MediaPipe Hand Landmarker로 손 21개 점 검출, 관절 각도로 손가락별 펴짐 판정
5. **선행 조준**: 탄 도착까지 걸리는 프레임 수 k를 구하고, Kalman 상태로 k프레임 뒤 공 위치를 예측해 LOCK 판정
6. **발사·명중 판정**: 엄지를 접는 순간 발사, 탄과 공 위치의 거리가 반지름보다 작으면 HIT
7. **화면 출력**: 오버레이, 점수, FPS, 남은 탄약, 종료 판정

## 4. 창의성 및 확장성

### 아이디어 설명
과제 조건인 "객체를 인식·추적하고 신체와의 관계성을 표현"을 **"손가락이 공을 겨누고 있는가"**로 정의했습니다. 움직이는 표적을 맞히려면 표적의 현재 위치가 아니라 **탄이 도착할 때의 위치**를 겨눠야 한다는 선행 조준 개념을 적용했습니다.

기존 실습 코드 세 개(`realtime_object_detection.py`, `realtime_object_tracking_02.py`, `finger_tip.py`)의 결과가 모두 같은 픽셀 좌표계라는 점을 이용해, 공의 위치와 손가락 방향을 직접 비교하도록 연결했습니다.

### 구현한 내용

**1) 선행 조준 (Kalman Filter로 미래 위치 예측)**

기존 실습에서는 Kalman Filter를 공이 가려졌을 때 위치를 이어가는 데만 사용했지만, 상태에 속도가 포함되어 있으므로 상태 전이 행렬 F를 여러 번 곱하면 미래 위치도 구할 수 있습니다.
```
k = 거리(검지 끝 ~ 공) / 탄 속도   (1 ~ 30 프레임으로 제한)
미래 상태 = F^k × 현재 상태  →  (x + k·vx, y + k·vy)
```

**2) 조준 판정 (각도 비교)**

`finger_tip.py`의 `calculate_angle`과 같은 원리(내적)로 두 벡터 사이 각도를 구하는 `vector_angle` 함수를 만들었습니다.
- 조준 방향: 검지 뿌리(5번) → 검지 끝(8번)
- 표적 방향: 검지 끝 → 공 예측 위치
- 두 방향 사이 각도가 **그 거리에서 공이 차지하는 각도** `arctan(반지름 × 1.5 / 거리)`보다 작으면 LOCK

멀리 있는 공일수록 허용 각도가 작아져서 더 정확하게 겨눠야 합니다.

**3) 손가락 총 제스처**

`finger_tip.py`의 손가락 개수 세기를 손가락별 True/False 리스트로 바꿔, 손가락마다 다른 역할을 주었습니다.
- 검지가 펴져 있으면 조준
- 조준 중 엄지가 접히면 발사 자세
- 직전 프레임 상태(`prev_fire`)와 비교해서 **엄지를 접는 순간에만** 한 발 발사 (접고 있는 동안 연속 발사 방지)

**4) 명중 판정과 게임 규칙**
- 탄은 매 프레임 조준 방향으로 `bullet_speed`만큼 이동하고, 그 프레임의 공 위치(노란 원)와의 거리가 반지름보다 작으면 HIT
- 예측 위치가 아니라 그 프레임의 공 위치로 판정하므로, 선행 조준을 해야 명중
- 탄 속도와 탄약 수를 실행 시 입력받고, 탄약의 절반 이상 명중 시 MISSION COMPLETE, 탄약 소진 시 NO AMMO
- 마지막 탄의 판정이 끝난 뒤 종료되도록 `bullet is None` 조건을 함께 확인

**5) 기존 실습 코드에서 바꾼 부분**

| 내용 | 이유 |
|---|---|
| Kalman 최초 검출 시 `statePost`도 초기화 | `predict()`는 `statePost`를 기준으로 계산하므로, `statePre`만 설정하면 첫 예측이 (0, 0)으로 끌려감 |
| 30프레임 이상 안 보이면 추적 종료 | 공이 사라진 뒤 예측만 무한히 이어지는 것 방지 |
| 면적 100 이하 contour 무시 | 작은 노이즈를 공으로 오인하는 것 방지 |
| Opening 후 Closing 추가 | 공 안쪽 반사광으로 생긴 구멍 메우기 |
| `flip(frame, 0)` → `flip(frame, 1)` | 상하 반전이 아니라 거울처럼 좌우 반전되도록 만들어서 손 움직임과 화면 방향이 일치 |
| 1~3 키로 화면 전환 | 원본 / 마스크 / 결과를 바꿔 보며 중간 과정을 확인 |

### 한계
- **등속 운동 가정**: 공이 방향을 바꾸거나(진자 끝, 튕김) 속도가 변하면 예측이 빗나감
- **k 계산의 근사**: 도착 프레임 수를 현재 위치까지 거리로 계산하고 소수점을 버리기 때문에, 실제 만나는 시점과 1프레임 정도 차이가 날 수 있음
- **탄의 이산 이동**: 탄이 한 프레임에 `bullet_speed` 픽셀씩 이동하므로, 공이 작으면 두 위치 사이로 지나쳐 판정을 놓칠 수 있음
- **색 기반 검출**: 배경에 비슷한 초록색 물체가 있거나 조명이 크게 바뀌면 LAB 범위를 다시 맞춰야 함
- **제스처 판정**: 엄지는 2번 관절보다 뿌리 쪽에서 많이 움직여서, 각도 기준만으로는 접힘 판정이 불안정할 수 있음
- 손이 2개 검출되면 첫 번째 손만 조준에 사용

### 확장성
- **비등속 모델**: 상태에 가속도를 추가(등가속 모델)해서 방향이 바뀌는 표적 예측
- **유도탄**: 발사 후에도 매 프레임 예측 위치로 방향을 수정하는 방식(비례항법 등)으로 확장
- **딥러닝 검출**: 색 기반 검출을 YOLO 같은 객체 검출 모델로 바꿔 다양한 표적에 대응
- **요격 드론 연구와 연결**: 카메라 기반 표적 추적과 선행 예측은 실제 요격 드론의 유도에 쓰이는 개념과 같은 구조

## 5. 기타 참고 사항

### 작업 중 겪은 문제와 해결
- **라즈베리파이로 Jetson 환경 재현**: 개인 라즈베리파이 + USB 카메라에서 Jetson과 같은 Python 3.10 가상환경을 만들어 먼저 테스트했다. MediaPipe를 `--no-deps`로 설치했더니 `certifi`가 없다는 에러가 났는데, Jetson은 `--system-site-packages`로 시스템 패키지를 빌려 쓰기 때문에 괜찮았던 것이었다. 빠진 패키지를 설치해서 해결했다.
- **GStreamer 파이프라인 문자열**: 파이프라인을 여러 줄로 나눠 쓰면서 줄 끝 공백과 `!`를 빼먹어서 문자열이 `format=BGRqueue`처럼 붙어버렸고, 카메라가 열리지 않았다. 파이썬은 괄호 안 문자열을 공백 없이 그대로 이어 붙인다는 것을 알게 되었다.
- **왼손/오른손 라벨**: MediaPipe는 `"Left"`, `"Right"`로 값을 주는데 `"RIGHT"`와 비교해서 항상 같은 라벨만 나왔다. 비교하는 문자열을 원래 값과 맞춰서 해결했다.
- **마지막 탄 판정**: 처음에는 `shot == 30`이 되는 순간 바로 종료해서 마지막 탄이 판정을 받지 못했다. 날아가는 탄이 없을 때(`bullet is None`) 종료하도록 바꿨다.
- **입력값 처리**: 처음에는 발사 모드를 문자열로 입력받아 `prev_fire`에 넣었는데, `"False"`도 비어 있지 않은 문자열이라 참으로 처리되어 동작하지 않았다. `prev_fire`는 원래 용도(직전 프레임 발사 자세)로만 쓰고, 탄 속도와 탄약 수만 입력받도록 정리했다.
